# Project memory: Monitoring Engineering

## Purpose and stack

Equipment monitoring web app for Interbat. Technicians record machine readings by shift and round; admins configure machines, parameters, schedules, users, and report recipients. Built with React 18, TypeScript, Vite, Tailwind CSS, Supabase (Auth, Postgres/PostgREST, Storage, Edge Functions), and jsPDF/autotable for reports.

## Main user flows

- `src/App.tsx` gates the app on Supabase authentication, profile existence, and active status; admins get extra routes.
- `src/components/Layout.tsx` provides navigation.
- Technician pages: dashboard, new monitoring, history, reports, parameter trends, and work requests (titipan pekerjaan).
- Admin pages: machines, parameters, schedules, users, report email recipients, and audit trail.
- Admin-only `Machine For Holiday (MFD)` page manages holiday activation separately from each machine's regular `is_active` flag. It references existing machines and provides per-machine plus bulk activate/deactivate controls; the setting is stored in `holiday_machine_settings` (migration `20261103090000_holiday_machine_settings.sql`). Regular Machines now has an inline status toggle beside each machine in the Machine column.
- `src/lib/AuthContext.tsx` maps usernames to `<normalized_username>@monitor.local`, supports sign-in and edge-function account creation, writes auth audit events, and signs out after five idle minutes.
- `src/lib/types.ts` contains core domain types and shift/round helpers. Shifts are 07–15, 15–23, and 23–07; each has two four-hour rounds. Numeric readings are classified normal/warning/abnormal against configured bounds, with 10% warning tolerance.
- `src/pages/NewMonitoring.tsx` handles scheduled parameter entry, conditional parameters, reading validation, photos, and round saving/editing. Parameters can require photos or enforce increasing cumulative values.
- Reports/history use stored round values and photos; PDF generators are in `src/lib/*PdfReport.ts` and `src/lib/pdfReport.ts`. The shift email report is generated by `supabase/functions/send-shift-report/index.ts`.

## Data model and backend

Supabase migrations in `supabase/migrations/` define profiles/roles, machines and machine parameters, parameters, schedules and scheduled parameters, monitoring rounds/values/photos, report recipients, work requests/photos, audit logs, and round conclusions. Photos use the public `monitoring-photos` bucket. RLS policies and audit triggers are defined in SQL migrations; edge functions include create-user, delete-user, and send-shift-report.

Important business constraints recorded in migrations and `README_PERUBAHAN.txt`: a machine/date/shift/round cannot be duplicated; an existing round is loaded for editing; monitoring is restricted to its active shift window (with DB-side protection); there is one shared conclusion per date/shift/round, not one per machine. Schedule parameters may depend on another parameter's value.

## Local proxy deployment

`README_PROXY.md` documents offline-LAN-client mode. `npm run build:proxy` runs `server/build-local-proxy.ps1`; the Node server `server/proxy-server.mjs` serves `dist/` and forwards `/rest/v1`, `/auth/v1`, `/storage/v1`, and `/functions/v1` to Supabase. `server/start-monitoring.bat` starts the proxy; default port is 4000. `.env.local-proxy` configures the upstream and should not be committed. `BACA-DULU.txt` is the quick start guide.
